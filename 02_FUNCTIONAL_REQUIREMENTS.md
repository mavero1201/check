# Functional Requirements

## 1. Общая логика продукта

Сайт должен принимать файл с анкетой количественного исследования, извлекать текст, передавать его AI-модулю проверки и отображать структурированный отчет.

## 2. Главная страница

На главной странице должны быть:

- заголовок продукта;
- краткое описание сервиса;
- блок drag-and-drop загрузки;
- кнопка выбора файла;
- список поддерживаемых форматов;
- предупреждение, что сервис предназначен именно для количественных анкет.

## 3. Загрузка документа

Система должна поддерживать:

- drag-and-drop;
- выбор файла через системный диалог;
- форматы: PDF, DOCX, TXT;
- базовую валидацию размера и типа файла;
- состояние загрузки;
- понятное сообщение об ошибке при неподдерживаемом формате.

## 4. Извлечение текста

После загрузки система должна:

- извлечь текст из документа;
- сохранить структуру по возможности: блоки, вопросы, варианты ответов;
- передать извлеченный текст в AI-анализатор.

## 5. AI-анализ

AI-анализатор должен:

- интерпретировать документ как количественную анкету;
- разбить контент на вопросы и варианты ответов;
- выполнить проверку по встроенному набору правил;
- классифицировать найденные замечания по типам;
- присвоить уровень критичности;
- выдать рекомендации.

## 6. Категории замечаний

Минимум должны быть следующие категории:

- Кодировка и полнота вариантов ответа;
- Диапазоны и покрытие значений;
- Соответствие вопроса и ответов;
- Методологические ошибки;
- Наводящие или предвзятые формулировки;
- Стилистика и тональность;
- Ясность и однозначность формулировок;
- Общие стандартные проверки количественной анкеты.

## 7. Формат отчета

Отчет должен содержать:

- summary-блок с количеством замечаний;
- секции по категориям;
- карточки замечаний;
- для каждой карточки:
  - уровень критичности;
  - тип ошибки;
  - фрагмент текста;
  - объяснение;
  - рекомендацию;
  - при желании — пример улучшенной формулировки.

## 8. Уровни критичности

Использовать минимум 4 уровня:

- Critical — ошибка, способная повлиять на валидность данных или программирование;
- Major — важная методологическая проблема;
- Minor — нежелательная, но не блокирующая ошибка;
- Recommendation — улучшение качества.

## 9. UX-требования

Интерфейс должен быть простым, профессиональным и минималистичным.

Нужно предусмотреть:

- состояние пустого экрана;
- состояние загрузки;
- состояние обработки;
- состояние ошибки;
- готовый отчет;
- кнопку скопировать результат.

## 10. Нефункциональные требования

- адаптивность для desktop и laptop как приоритет;
- чистый современный UI;
- понятные тексты без технического жаргона;
- безопасная обработка загружаемых файлов;
- отсутствие хранения файла дольше необходимого в MVP.

## 11. Что не входит в MVP

- авторизация;
- личный кабинет;
- история загрузок;
- совместное редактирование;
- интеграции со сторонними survey-платформами;
- автоисправление документа в исходном файле.
