# Acceptance Criteria for MVP

## 1. Загрузка

- Пользователь может перетащить файл в drag-and-drop зону.
- Пользователь может выбрать файл кнопкой.
- Неподдерживаемые форматы корректно отклоняются.
- Пользователь видит понятное сообщение об ошибке.

## 2. Обработка документа

- После загрузки документ передается в пайплайн обработки.
- Текст извлекается как минимум из TXT, DOCX и PDF.
- Пользователь видит статус обработки.

## 3. Генерация отчета

- После анализа пользователь получает структурированный отчет.
- В отчете есть summary по уровням критичности.
- В отчете есть минимум одна секция с найденными замечаниями.
- Каждое замечание содержит описание проблемы и рекомендацию.

## 4. Качество методологической проверки

Система способна находить как минимум следующие типы проблем:

- дубли кодов;
- отсутствие «другое», где это ожидается;
- отсутствие «затрудняюсь ответить / не знаю», где это логически ожидается;
- пересечение диапазонов;
- разрывы диапазонов;
- несоответствие ответов вопросу;
- наводящие или перегруженные формулировки;
- стилистическую непоследовательность «Вы/вы».

## 5. UX

- Интерфейс читаемый и аккуратный.
- Пользователь понимает, что делать на каждом этапе.
- Отчет удобно читать и копировать.

## 6. MVP готов к демонстрации, если

- сайт запускается локально без существенных доработок;
- можно загрузить пример файла;
- можно получить результат анализа;
- визуально продукт выглядит как профессиональный рабочий MVP, а не как черновой прототип.
